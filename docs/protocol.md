# TH Cross Worker Protocol

This document defines the initial protocol between the cross-side GHC plugin
and the native host-side Template Haskell worker.

The protocol is intentionally textual. The host worker returns generated
Haskell source fragments, not GHC AST values. The cross GHC parses the returned
fragment with its own parser and continues normal renaming, typechecking, and
code generation.

## Transport

The MVP transport is JSON Lines over stdin/stdout:

```text
cross GHC plugin writes one JSON request line to worker stdin
host worker writes one JSON response line to stdout
```

Each message is exactly one JSON object followed by `\n`.

Worker diagnostics must go to stderr. Stdout is reserved for protocol
responses.

## Splice Kinds

The `spliceKind` field is one of:

```text
expression
type
pattern
declaration
annotation-wrapper
```

The current prototype supports `expression`, `type`, `pattern`, and
`declaration`. `annotation-wrapper` is supported only as an internal
same-GHC-version helper for replaying annotation declarations produced by
`addTopDecls`.

## Request

```json
{
  "requestId": "123",
  "module": "My.Project.Foo",
  "componentUnitId": "my-package-0.1.0.0-abc123-my-exe",
  "sourceFile": "/path/to/My/Project/Foo.hs",
  "spliceKind": "expression",
  "sourceSpan": {
    "startLine": 42,
    "startColumn": 7,
    "endLine": 42,
    "endColumn": 24
  },
  "spliceKey": "2bfc6d6f9f7d6abdfb5dbb5c8ab8d3d1",
  "spliceExpression": "genFoo 123",
  "crossGhcVersion": "9.8.4",
  "hostPackageIds": [
    "microlens-0.4.14.0-1VGRH8KhtCiFJuTK8ISqfF",
    "microlens-th-0.4.3.17-GmrnQrlDn7K6e99RCCjC8F"
  ],
  "hostSourceDirs": [
    "src"
  ],
  "hostGhcOptions": [
    "-Dandroid_HOST_OS"
  ]
}
```

Fields:

- `requestId`: unique request id generated by the cross-side plugin.
- `module`: module name containing the splice.
- `componentUnitId`: GHC unit id of the component currently compiling the
  module. The worker uses this to scope its in-process expansion cache, so the
  same source splice compiled by different Cabal components does not reuse the
  wrong expansion.
- `sourceFile`: source path reported by the cross-side compiler.
- `spliceKind`: splice category.
- `sourceSpan`: 1-based source span of the splice expression.
- `spliceKey`: opaque stable splice identity used as the worker-side matcher.
  It is derived from module name, splice kind, and source span.
- `spliceExpression`: pretty-printed splice expression.
- `crossGhcVersion`: GHC version of the cross compiler process.
- `hostPackageIds`: exact host-side unit ids that the worker should expose in
  the native GHC session. This corresponds to GHC's `-package-id` and avoids
  ambiguity between multiple package instances with the same package name.
- `hostSourceDirs`: extra source directories that the worker should add to the
  native GHC session's import path. This is needed when the splice module imports
  another source module from the same package, for example an executable module
  importing its package's library component.
- `hostGhcOptions`: extra GHC command-line options that the worker applies to
  the native GHC session before loading the module. The intended first use is
  forwarding target-like preprocessing options such as `-D`, `-U`, `-I`, and
  `-optP` so host-side `reify` observes the same CPP-shaped source as the
  cross-side compiler.

## Successful Response

```json
{
  "requestId": "123",
  "status": "ok",
  "generatedHaskell": "42",
  "annotationWrapper": null,
  "dependentFiles": [],
  "foreignFiles": [],
  "addedTopDecls": "",
  "diagnostics": []
}
```

`dependentFiles` contains files registered by host-side Template Haskell through
`addDependentFile`. The cross-side plugin must replay these into the cross GHC
session.

`foreignFiles` contains files registered by host-side Template Haskell through
`addForeignFilePath`. The cross-side plugin replays these into the cross GHC
session so the target-side build can compile/link them.

Foreign file entry:

```json
{
  "language": "c",
  "path": "cbits/generated.c"
}
```

`language` is one of `c`, `cxx`, `objc`, `objcxx`, `asm`, `js`, or
`raw-object`.

`addedTopDecls` contains top-level declarations registered by host-side Template
Haskell through `addTopDecls`, rendered as textual Haskell. The cross-side plugin
parses this fragment and appends the resulting declarations to
`tcg_th_topdecls`.

`annotationWrapper` contains a binary-encoded GHC `Serialized` value used only
for `annotation-wrapper` responses. This is intentionally not a cross-version
textual format. It exists so the GHC 9.8.4 prototype can replay `AnnD`
declarations generated through `addTopDecls`; host and cross GHC must agree on
the relevant internal binary representation.

`diagnostics` contains diagnostics registered by host-side Template Haskell
through `reportWarning` or `reportError`. In GHC 9.8.4 both operations are
represented internally as `TcRnTHError (ReportCustomQuasiError isError message)`;
the `isError` flag distinguishes warning from error. The cross-side plugin
replays those diagnostics into the current GHC session.

Diagnostic entry:

```json
{
  "severity": "warning",
  "message": "generated code uses a fallback"
}
```

`severity` is either `warning` for `reportWarning` or `error` for `reportError`.

Fields:

- `requestId`: request id copied from the request.
- `status`: `"ok"`.
- `generatedHaskell`: Haskell fragment to parse in the cross GHC process.
- `annotationWrapper`: same-version binary annotation-wrapper payload, or
  `null` for normal textual splice results.
- `dependentFiles`: files to register in the cross GHC session as TH
  dependencies.
- `foreignFiles`: foreign files to register in the cross GHC session.
- `addedTopDecls`: textual declarations to register in cross-side
  `tcg_th_topdecls`.
- `diagnostics`: host-side TH diagnostics to replay in the cross GHC session.

## Error Response

```json
{
  "requestId": "123",
  "status": "error",
  "message": "failed to evaluate splice"
}
```

Fields:

- `requestId`: request id copied from the request, if known.
- `status`: `"error"`.
- `message`: human-readable error text.

## Versioning

The first prototype has no explicit protocol version field. Backward-compatible
fields may be added later. The first breaking change should add:

```json
{
  "protocolVersion": 1
}
```

to both request and response objects.
